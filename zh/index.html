deki-tactility-integration

让 Deki 游戏作为应用运行在 Tactility（面向 ESP32 开发板的操作系统）中，而不是作为占据整个设备的固件。

仓库：github.com/dekiengine/deki-tactility-integration · 最新版本：0.21.0 · 需要引擎 0.19.0 或更高版本 · 依赖：deki-input

使用 DekiEditor --packages-add deki-tactility-integration <project> 或通过包管理器安装。引擎自身的组件和 C++ API 见 Deki 文档。

在编辑器中显示为 **Tactility Integration**。

组件

组件 类别 说明
TactilityDisplaySetup Tactility 为游戏提供 Tactility 的显示屏：整个面板，或在系统仍运行时的一个窗口。
TactilityInputSetup Tactility 将 Tactility 的触摸和键盘输入传入 Deki 的输入系统。

功能开关

可以从构建中去掉的部分。带有 define 的功能通过该 define 开关，其余的随其组件一起被剥离。

功能 define 默认值
Display — 开
Input — 开

组件参考

TactilityDisplaySetup

为游戏提供 Tactility 的显示屏：整个面板，或在系统仍运行时的一个窗口。

检视器中的名称：Tactility 显示屏设置 · 类别：Tactility · 类型：DekiTactility::TactilityDisplaySetup

属性 类型 默认值 约束 说明
mode enum "Panel" Panel, Window 面板模式接管整个显示屏并停止 LVGL，游戏独占每个像素。窗口模式在应用窗口中运行游戏，LVGL 和系统仍在周围运行，大小为平台的屏幕大小。

TactilityInputSetup

将 Tactility 的触摸和键盘输入传入 Deki 的输入系统。

检视器中的名称：Tactility 输入设置 · 类别：Tactility · 类型：DekiTactility::TactilityInputSetup

没有反射的属性。

更新日志

更新日志为英文。

0.21.0

Changed

  • F:/ works as on a board: files the game writes under F:/ go to internal/ in the app's user data, read from there when the app's assets have no file of that name, and the assets are never written. Before, a game could not write under F:/ at all on Tactility.
  • Scenes open from the SD card again. The app gave every allocation to plain malloc, which puts anything under 16 KB in internal RAM, so a scene's objects and strings took the internal RAM Tactility needs for itself: the SD card driver could not get a DMA buffer, every file read failed, and a scene switch found no scene. TactilityMemoryProvider uses Tactility's own allocator: ordinary allocations prefer PSRAM, and only what the engine asks to keep internal (with DMA when asked) is internal.
  • The temporary frame-timing log (PROBE, every 2 s) is gone.

Fixed

  • Apps that use the Tiled package load again: strnlen, unsigned 64-bit division (__udivdi3) and std::list's node functions are defined for device apps (TactilityLibc.c, TactilityLibcxx.cpp); Tactility does not export them.

0.20.3

Fixed

  • The device SDK and app builds enter ESP-IDF from its own directory, so they work where sh is dash (Ubuntu, Debian). There, export.sh could not find ESP-IDF and the TactilitySDK build stopped at once.
  • nextafterf is defined for device apps (TactilityLibc.c): Tactility does not export it, and deki-2d 0.20.1's cropped text calls it, so the device refused the app.
